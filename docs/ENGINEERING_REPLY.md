# 工程回覆：教材、教材檢視與注記

回覆《學習單產生器：教師選項與 SOP 整合規格》（2026-11-14）§12 第 1、11、12、13 項。依規格要求，下列只說明可行性、做法、限制與估時；沒有改變任何產品需求。凡標「已完成」者已在 Phase 2.2（Migration `0009_materials.sql`，合約見 `docs/API.md`「Phase 2.2：教材與注記」）實作並有自動測試；標「待確認」者需要主持人決定。

估時以一位工程師、含測試與文件的工作天計。

## 第 1 項：各類上傳素材的副檔名、單檔大小、數量上限與影音處理方式

### 已完成

| 類型 | 副檔名 | 單檔上限 | 平台怎麼處理 |
|---|---|---|---|
| 文件 | `.txt`、`.docx`、`.pdf` | 20 MB | 保存原檔、擷取文字並分段（含 PDF 頁碼），可對照、注記、請 Manna 分析 |
| 圖片 | `.png`、`.jpg`／`.jpeg`、`.webp`、`.gif` | 10 MB | 保存原檔，在教材檢視區顯示；不分析 |
| 音訊 | `.mp3`、`.m4a`、`.wav` | 30 MB | 保存原檔，用瀏覽器內建播放器播放（可拖曳進度）；不轉檔、不分析 |
| 影片 | `.mp4`、`.webm` | 100 MB | 同音訊 |
| 貼上文字 | — | 50,000 字 | 程式分段（與原本課例 SOP 相同的規則） |
| 素材網址 | — | 2,000 字元 | 只存網址、標題與來源說明；不抓取、不複製網頁內容（著作權，§9.7） |

- **數量上限**：每位教師最多 300 份教材（任何類型），上傳檔案合計 1 GB。教材庫頁面顯示已使用的空間。
- **為什麼是這些數字**：正式主機是 2 核心、8 GB。上傳的檔案在檢查大小、檔頭與計算 SHA-256 時會放在記憶體裡，同時最多處理 2 個（其餘排隊），最壞情況約 200 MB；PDF 文字擷取在背景執行緒進行，20 MB 的文件數秒內完成。1 GB／人 × 研究規模（數十位教師）在一般磁碟容量內。這些數字都是程式常數，要調整只改一處（`api/src/materials/mod.rs`）。
- **格式檢查**：先看副檔名，再看檔案開頭的格式標記；副檔名對但內容不符（例如改名的執行檔、叫 `.png` 的網頁）一律拒收。`.doc`、`.ppt(x)`、`.svg`、`.html` 不收。同一位教師重複上傳同一個檔案會提示已經在教材庫。
- **影音**：只保存與播放，不轉檔、不產生字幕、不做語音辨識。下載與播放一律經過後端並檢查擁有者，支援分段讀取（Range），所以大影片可以直接拖曳到中間播放。

### 待確認

1. 是否需要 `.pptx`（投影片）？可行：擷取每張投影片的文字並以「第 n 張」定位，約 **1.5 天**。舊版 `.doc`／`.ppt` 需要外部轉檔程式（LibreOffice，映像會大約 500 MB），不建議。
2. 影片 100 MB 約是手機錄的 2–4 分鐘 1080p。若教師常用較長的影片，建議改為貼 YouTube 等網址，而不是放大上限。
3. 音訊／影片的語音轉文字（讓影音也能對照與注記）：需在核准環境部署語音辨識模型（國網中心或自架 Whisper 類模型），2 核心主機無法自行負擔。接上已有的辨識 API 約 **3 天**（含時間軸定位）；自架另計硬體。

## 第 11 項：第一版文件與文字注記的檔案格式、文字擷取、選取、頁面／段落定位及 OCR 範圍

### 已完成

- **可注記的教材**：貼上的文字、`.txt`、`.docx`、有文字層的 `.pdf`。
- **文字擷取**（全部以 Rust 實作，不呼叫外部服務，教材不離開平台）：
  - TXT：UTF-8、UTF-16、Big5（舊版 Windows 記事本常見）。
  - DOCX：依文件順序取出每個段落，包含表格內與文字方塊內的段落；追蹤修訂中「已刪除」的文字不算。
  - PDF：逐頁擷取。PDF 本身沒有「段落」，平台以空行、句末標點與行長判斷段落，並把行尾斷字接回；每一段記下起始頁碼，檢視區顯示「第 n 頁」分隔。
- **段落定位**：每段有編號（¶1、¶2…，頁邊顯示）與穩定的段落 id；貼上的文字修改後，沒改的段落沿用原 id，所以課例 SOP 與注記不會因為改了別段而錯位。
- **選取**：在教材檢視區直接用滑鼠選取文字，出現「加注記」。選到英文單字的一半時自動延伸到整個單字；一則注記只能在同一段內（跨段落選取會提示）。
- **掃描文件**：沒有文字層的 PDF 照常保存、預覽與下載，畫面清楚說明「沒有可以選取的文字（可能是掃描檔），目前不做文字辨識（OCR）」，不能注記、也不能請 Manna 分析。

### 限制

- PDF 分段是推測：兩欄排版、表格、頁首頁尾、註腳可能被切成奇怪的段落或順序。教師可改為貼上文字。
- 加密或損壞的 PDF 讀不出文字（畫面說明，原檔仍保存）。
- 超過 30 萬字的文件只擷取前面的文字（畫面註明，原檔完整保存）。

### 待確認：OCR

- **可行性**：可行，但必須在核准環境處理（教材可能含受著作權保護的內容，且規格禁止送境外服務）。
- **方案 A（建議）**：使用國網中心若有提供的 OCR 或多模態模型 API，以背景工作處理（掃描檔 20 頁約 1–3 分鐘），結果標示「文字辨識結果，可能有誤」，教師可修正後再注記。約 **4 天**（背景工作、進度顯示、低信心標示、測試）。
- **方案 B**：在主機上跑 Tesseract（英文辨識尚可，中英混排與手寫較差），映像增加約 100 MB，2 核心主機一次只能處理一份，20 頁約 1–2 分鐘。約 **3 天**。
- 兩者都不影響目前的資料結構（辨識出的文字照樣成為段落）。

### 後續可行性評估（不列入第一版，依規格）

- **圖片區域注記**：在圖片上框選區域並加注記，存相對座標（0–1）。資料表可沿用（加一個區域欄位）。約 **3 天**。
- **音訊／影片時間點注記**：在播放器目前時間加注記，存秒數區間。約 **2.5 天**。

## 第 12 項：並排區域的大小調整、收合、全螢幕、較小螢幕及行動裝置呈現方式

### 已完成（同一個元件 `MaterialViewer`，課例 SOP 與學習單產生器共用）

| 情境 | 呈現 |
|---|---|
| 課例 SOP 第 2–7 步「對照教材」 | 教材從左側滑出，停在步驟旁邊（寬螢幕時進度列讓位，步驟往右移）；「收起教材」或 Esc 關閉 |
| 學習單產生器（並排欄） | 教材是一欄，與設定／結果／編修區並排；拖曳分隔線或用鍵盤左右鍵調整寬度（320–760px，瀏覽器記住上次的寬度）；「收起教材」收成一個直立的「對照教材」按鈕；「全螢幕」讓教材佔滿畫面 |
| 寬度 1100px 以下 | 並排欄改為蓋在頁面上（有陰影），不擠壓工作區 |
| 寬度 760px 以下（手機） | 兩種用法都變成全螢幕的教材頁，頂端固定「收起教材」 |

- 教材檢視區的內容在兩種用法完全相同：印刷樣式的原文、頁邊段落編號、PDF 頁碼、教師注記與 AI 開關、圖片與影音預覽。
- 依 `docs/DESIGN_OVERHAUL.md`：備課以電腦為主，手機（375px）不壞、可閱讀與注記，但不是主要情境。
- 截圖：`docs/design/overhaul/implemented/materials/`（`pane-desktop-preview.jpg` 是把並排欄暫時放在學習單頁上的本機預覽，學習單產生器由另一個 PR 實作）。

### 限制

- 手機上選取文字需長按，系統的選取工具列會蓋住部分畫面；手機注記可用但不順手，符合「手機只做查看」的方向。

## 第 13 項：注記的資料結構、定位穩定性、版本關係、權限、刪除、匯出及原始教材變更後的失效處理

### 資料結構（已完成）

每則注記一列（`material_annotations`），與教材分開存，**從不改寫教材**：

| 欄位 | 內容 |
|---|---|
| `material_id` | 屬於哪一份教材 |
| `paragraph_id`、`start_offset`、`end_offset` | 段落 id 與段落內位置（與瀏覽器選取相同的計算方式） |
| `quote`、`prefix`、`suffix` | 標記的原文，以及前後各 32 字的上下文（由伺服器從教材取出，不採用瀏覽器送來的文字） |
| `note` | 注記內容（≤ 2,000 字） |
| `share_with_ai` | 「提供給 AI」，**預設關閉** |
| `hidden` | 隱藏（不刪除） |
| `material_revision` | 做注記時教材的修訂次數 |

### 定位穩定性與失效處理（已完成）

每次開啟時重新找位置：

1. 同一段、同一位置的文字沒變 → 照原位置顯示。
2. 教材改過，但同一段（或另一段中唯一最吻合的地方）還找得到原文 → 移到新位置顯示（以上下文判斷同一段中多處相同的字）。
3. 找不到 → 注記保留，排在最上方並標示「**需要重新確認位置**」，說明教材改過；教師可以「重新選位置」（直接在教材中選取新的文字）或刪除。這種注記不會提供給 AI。

### 版本關係

- 教材本身不保留舊版本：教師修改貼上的文字時就地修改，修訂次數加 1。這是刻意的：規格要求教師刪除教材時原文必須真的消失，保留舊版本就做不到。
- 課例 SOP 的版本記得當時教材的修訂次數；檢視舊版本時看到的是教材**現在**的樣子。
- 學習單版本與注記的關係：學習單產生器把教材連到學習單（`material_links`），注記跟著教材走，所以重新開啟學習單或其連結課例時，注記會重新載入（規格 §4.4 第 8 點）。若之後需要「學習單產生時用的是哪些注記」，建議在學習單版本中記注記 id 與內容雜湊（不記內容），約 **0.5 天**，由學習單產生器實作。

### 權限（已完成）

- 教材與注記只有擁有的教師看得到、改得到；其他帳號（包括主持人與研究助理的教師端點）一律 404，不洩漏是否存在。
- 新增能力 `use_materials`，目前所有角色都有，日後要收窄只改一處。
- **給 AI 的只有勾了「提供給 AI」、沒有隱藏、找得到位置的注記**，而且只有一個入口（`annotations::shared_with_ai`），送給模型時固定標明「教師注記（不是教材原文，也不是外部來源；不得寫進學生版）」。
- 注記不會出現在學生版或任何學生端輸出：學生版由學習單產生器產生，它只能透過上述入口拿到注記，且只作為生成脈絡。

### 刪除（已完成）

- 刪除注記：只刪注記，教材不變。刪除前頁內確認。
- 刪除教材（頁內確認，明說永久刪除、無法復原、會影響哪些課例）：原檔物件、擷取的文字與段落、所有注記、課例與學習單的連結一起刪除；課例顯示「教材已刪除」，課例與 AI 紀錄中從教材逐字引用的片段換成「［教材已刪除］」，教師自己寫的分析、目標、任務保留。原檔刪不掉時整個不刪並告知教師，不會留下沒人管得到的檔案。
- 平台只留下一筆「某教材在某時被刪除」的紀錄（類型、大小、注記數），沒有標題、檔名、雜湊或內容。

### 匯出（待實作，屬學習單產生器）

- 規格 §9.7：注記是否納入匯出的教師參考資料由教師選擇。建議在學習單匯出時提供「附上我的教材注記」選項（預設不勾），只出現在**教師參考版**，格式為「¶段落編號「原文」→ 注記」。學生版永遠不含注記。約 **1 天**（DOCX 與 PDF 各一種版面），由學習單產生器 PR 實作。

### 仍需注意

- **資料庫備份**：已刪除教材的文字仍可能存在於刪除前的資料庫備份中，直到備份輪替過期；物件儲存不做版本保留，沒有備份副本。請主持人決定正式環境的備份保留天數（`docs/BLUEPRINT.md` §12）。
- **單元的「教材優先」菜單**（較早的單元教材功能）仍是獨立的貼上文字，尚未併入教材庫；合併約 **1 天**。

## 部署前需要的設定（Coolify）

在 manna 專案新增 MinIO 服務（Coolify 內建範本，映像 `ghcr.io/coollabsio/minio`；原本的 `minio/minio` 已不在 Docker Hub），只開內部網路；建 bucket `manna-materials`（**不開版本保留**）與一個只對這個 bucket 有讀、寫、刪、列權限的帳號；在 app 設 `STORAGE_BACKEND=s3`、`S3_ENDPOINT`、`S3_BUCKET`、`S3_ACCESS_KEY`、`S3_SECRET_KEY`。設定完成前網站照常運作，只是上傳會顯示「還沒有設定檔案儲存空間」，貼上文字與網址可以使用。
