# LLM 驗證：課例 SOP 與學習單產生器

- 日期：2026-11-14　狀態：驗證與前置作業，**未更動網頁介面與既有 API 行為**
- 對應規格：`學習單產生器_教師選項與SOP整合規格_20261114`（以下稱「規格」）
- 程式、prompt、schema、檢查函式與重跑方式：[`research/sop-validation/`](../research/sop-validation/README.md)
- 模型：國網中心 GenAI `gemma-4-31B-it`（OpenAI 相容，`response_format: json_schema`）
- 所有擷取文字、CSV、模型輸出都放在 repo 外的 `~/manna-data/`；課綱、詞彙表、教師學習單皆未進 repo。

## 0. 結論

1. **gemma-4-31B-it 可以支撐這套流程，但前提是分步、每步有自動檢查與一次修復，而且把「不能出錯的部分」交給程式。** 七個步驟的結構化輸出只要有回傳就一定符合 schema；硬性檢查第一次全過的比例依步驟差很多（(b)(f) 8/8、(d)(e) 7/8、(g) 18/24、(a) 4/8、(c) 2/8），修復一次後除 (a) 外都到 8/8 或 23/24。
2. **最可靠**：SIOP 內容／語言目標的區分與課綱連結（給清單時 58 筆引用的代碼全部存在）、Exit ticket、暖身字彙（級別由程式帶入）、規格標籤的使用（所有標籤都在允許集合內）、學生版全英文、答案不出現在學生版。
3. **不可靠、必須有防護**：逐字引用（常用「...」拼接兩句）；長陣列提早結束（(a) 有 3/8 次只輸出前 2 段，其中 2 次修復也救不回）；輸出失控（在陣列或空白字元中重複到 `max_tokens`，全部 461 次呼叫中 13 次）；LaTeX 殘留；速度（整條 chain 含三個版本約 5–12 分鐘）。
4. **不給條目清單時，模型寫出的 31 個課綱代碼格式全都「存在」，但它以為的條文 0 筆與真正條文相符**——代碼存在不代表連結正確，條文一定要由資料庫帶出。
5. **設計規則＋活動骨架範例沒有提高自動檢查通過率**（(c) 第一次 0/4 對 1/4、(g) 5/12 對 10/12），但題目更接近教師慣用寫法（句型開頭、分步指示）。建議規則經教師確認後再放入，範例暫不使用。
6. **知識庫擷取品質高**：課綱 1,352 條、詞彙表 6,012 詞條，皆有交叉驗證。缺：歷屆考題（完全沒有）、官方連結、綜合型高中的資料表類型、學習單清單 CSV（實收 270 份而非 276 份）。
7. **建議實作順序**：知識庫與詞彙分析（無 LLM）→ (a)(b) → (c)(d)(f) → (e)＋程式組裝＋版本調整。學習單組裝建議由程式完成，不交給模型。

## 2. 模型與 API 的實測限制

| 項目 | 實測 |
|---|---|
| Context 上限 | 262,144 tokens（超過時 API 回錯誤訊息；240,018 tokens 的輸入可成功，約 27 秒） |
| 輸出上限 | 未碰到硬上限（`max_tokens=60000` 可接受）；本次最長的結構化輸出 5,349 tokens。自由文字長文會在約 1,700 tokens 自行停下要求「Continue」 |
| 速度 | 下午約 70–95 tokens/s，晚間降到 30–45 tokens/s（共用服務，波動大） |
| 結構化輸出 | `json_schema` strict 可用；本次 約 450 次結構化呼叫中，回傳內容不是合法 JSON 的 0 次、不符 schema 的 0 次 |
| 失控重複 | 270 份學習單標註中有 3 份在 enum 陣列內無限重複同一個值（temperature 0），其中 2 份改用 temperature 0.5 仍失敗。**不設 `max_tokens` 時請求會卡到 HTTP 逾時**，而且之後一段時間其他請求也變慢或逾時 |
| 逾時 | chain 評估的 145 次呼叫中有 8 次 200 秒無回應（重試後成功） |
| 空白失控 | (g) 這類長輸出有另一種失控：在 JSON 內不停輸出空白與換行直到 `max_tokens`（chain 中 8 次，集中在 (g)） |
| 閘道快取 | **完全相同的請求會被快取**：失控後原樣重試，不到 1 秒就拿回同一個失敗結果。重試必須改變請求（本次改 temperature） |
| 陣列提早結束 | strict schema 不能限制陣列長度，模型有時只輸出前幾筆就收尾（見 §6.2 的 (a)） |
| 輸出怪癖 | 中英文欄位偶爾出現 LaTeX 箭頭 `$\rightarrow$`（JSON 解碼後變成亂碼）；段落編號曾輸出負數；會自行把英文人名譯成中文 |

結論：context 很充裕（整份該學校類型的高中階段課綱條目約 6 千 tokens，可整包放入）；真正的限制在**輸出端的穩定性與速度**，所以每一步都要設 `max_tokens`、逾時與重試，並把長輸出拆小。

### 3.2 擷取品質

- 5 份 PDF 都是文字型 PDF，**沒有掃描頁**（空白頁只有封面背面等）。
- 三份語文領綱：用表格擷取。純文字擷取會把表格左欄的直排類別標題混進條文，不可用。交叉驗證：
  - 全文出現過的代碼與擷取到的代碼完全一致（0 遺漏、0 多出）；各類別編號連續無缺號。
  - 同一條目在後面的對應表、附錄再次出現時，有 253 條可找到逐字相同的副本；其餘 19 條沒有逐字相同的副本，抽看其中 5 條都是附錄排版把下一列文字黏在一起或附錄用了略有不同的寫法，定義表的文字本身正確。
  - 普通型領綱的學習內容表是四欄並列、跨頁續排，有 8 條靠「同欄跨頁接續」規則接回（3-Ⅴ-13、Ae-Ⅲ-1、Ae-Ⅳ-1、B-Ⅳ-3、B-Ⅴ-2、B-Ⅴ-15、D-Ⅲ-3、D-Ⅳ-2），已逐條人工讀過，匯入前仍建議再對一次原文。
- 外語群：代碼與說明分在不同儲存格且常被合併，表格擷取不可用，改以文字座標重建行；全文 719 個代碼全部擷取到。說明文字跨行時靠縮排位置接續，**這份是四份中最需要人工抽查的**（特別是含長括號的商概、數概條目）。
- 詞彙表：三欄排版，依座標分欄後讀取。「依字母排序」區（含級別數字）為主要來源，「依級別排序」區獨立擷取作交叉驗證：兩區共同的 6,003 個詞條級別**零不一致**，六級各 1,002 條。已知瑕疵：原表 1 個詞條詞類少一個句點（`calm v./adj./n`），已容錯；1 個詞條被換行切開，已用規則接回。
- 詞彙表本身的限制：5 個詞同時列在兩個級別（capital、chair、measure、media、medium）；不收專有名詞、多數複合詞、規則衍生詞（re-、non-、-less、規則的 -ing/-ed 形容詞），片語完全沒有——這些直接影響 §8 的詞彙分析。

## 4. 學習單範例與設計規則

### 4.1 收到的資料

- 實際檔案 **270 份（DOCX 142、PDF 128）**，規格寫 276 份（146／130）。**`純學習單清單.csv` 與 `待確認清單.csv` 都不在交付資料夾內**，所以無法核對缺的 6 份是哪些，也沒有來源、納入理由與原始 SHA-256；本次另建 `files.csv`（編號 W001–W270、檔名、SHA-256）。
- 270 份都擷取得到文字（無掃描檔、無重複檔）。字數中位數約 6,500 字元，最長 78,000。版面、圖片與手繪圖表在文字中看不到；DOCX 的文字方塊另行擷取。
- 學習單內含教師姓名、校名、班級欄位，屬個資；任何要給模型當範例的內容都必須先去識別。

### 4.2 結構化清冊怎麼做、準不準

每份學習單呼叫模型一次（文字超過 15,000 字元者保留頭 11,000、尾 4,000；32 份被截斷），輸出固定 schema：版本／冊／課、類型、活動順序（每個區塊的活動類型、資訊處理功能、學生任務、作答方式——後三者只能用規格 §2、§5 的標籤）、三種鷹架、是否有暖身／收尾反思／學習目標／參考答案／分級。268 份成功，2 份因失控重複放棄；每份中位數 6 秒、輸入約 2,400、輸出約 700 tokens。

**人工抽查 16 份**（固定亂數種子抽樣；由執行本驗證的 AI 代理對照檔名與學習單頭尾文字逐欄判斷，**不是教師判讀**，只能當初步估計）：

| 欄位 | 正確 | 說明 |
|---|---|---|
| 版本／冊／課 | 16/16 | 無法判斷時會如實填「無法判斷」 |
| 是否有暖身 | 16/16 | 其中 2 份屬邊界（只有「看標題預測」一步） |
| 是否有收尾反思／自評 | 15/16 | 漏判 1 份（末端的策略反思題） |
| 是否列出學習目標 | 15/16 | 誤判 1 份（把 ORID 的「Objective」提問當成學習目標） |
| 學習單類型 | 12/16 | 4 份錯誤都在「綜合講義」與「課文閱讀理解」的界線上 |
| 作答方式 | 約八成 | 傾向把底線作答的簡答題標成「填空題」，所以填空題比例偏高 |

與關鍵字規則比對（兩者都不是標準答案）：暖身一致率 71%（模型較寬鬆，多判 73 份）、收尾反思 80%、學習目標 73%、參考答案 93%。因此下表中「暖身」「學習目標」的比例應視為上限。

### 4.3 清冊統計（268 份）

- 版本：龍騰 154、三民 36、東大 6、翰林 2、無法判斷 70。類型：綜合講義 171、課文閱讀理解 50、字彙 24、文法句型 11、其他 12。
- 指示語：英文 82%、中英混合 12%、中文 7%。
- 每份 4–7 個活動區塊（中位數 6）。閱讀型（221 份）82% 以暖身或找資訊開始、66% 以創造資訊結束。
- 資訊處理功能：發現 91%、創造 87%、分析 86%、整理 72%、比較 30%；86% 的學習單用到 3 種以上。首次出現的相對位置（0 開頭、1 結尾）：發現 0.00 → 分析 0.16 → 整理 0.45 → 比較 0.55 → 創造 0.75。
- 作答方式：填空 95%、簡答 68%、選擇 63%、配對 16%、表格整理 12%、圖像組織 8%、段落寫作 4%、是非 2%。
- 鷹架：分步指示 90%、標示關鍵字彙 83%、句型框架 72%、作答示例 68%、引導問題 48%、字詞表 40%、圖像組織 28%、部分完成的大綱 19%、小組／配對安排 18%、「逐步減少支持」0%。
- 有收尾反思或自評 19%；同份分級 14%；附參考答案 9%。

### 4.4 結構化設計規則

完整規則（含證據與對應的自動檢查）在 [`rules/design_rules.json`](../research/sop-validation/rules/design_rules.json)，放進 prompt 的精簡版在 [`rules/design_rules_for_prompt.md`](../research/sop-validation/rules/design_rules_for_prompt.md)。摘要：

| 編號 | 規則 | 證據 |
|---|---|---|
| DR-01 | 讀前→讀中→讀後；以暖身或找資訊開始，以學生產出結束 | 閱讀型 82%／66% |
| DR-02 | 功能有進程：發現→分析／整理→比較→創造 | 相對位置 0.00→0.16／0.45→0.55→0.75 |
| DR-03 | 一份至少用到 3 種功能；「比較資訊」要刻意設計 | ≥3 種 86%；比較僅 30% |
| DR-04 | 讀中以段落為單位，一份 4–7 個區塊 | 中位數 6 |
| DR-05 | 填空、簡答、選擇為主幹，再配 1–2 種其他形式；是非題少用 | 見 4.3 |
| DR-06 | 整理／比較的區塊優先用表格或圖像組織，先給欄位或示範一格 | 表格、配對在這兩類區塊占比最高 |
| DR-07 | 語言鷹架以句型框架、作答示例為主 | 72%／68% |
| DR-08 | 教學鷹架以標示關鍵字彙為主，圖像組織用於整理與寫作 | 83%／28% |
| DR-09 | 幾乎都有分步指示；分組安排寫在步驟裡 | 90%／18% |
| DR-10 | 暖身不需先讀完課文：標題預測、個人經驗、圖片／引言、先備字彙 | 閱讀型 ≤82% |
| DR-11 | 字彙放在語境中處理（語塊、搭配詞、引導翻譯） | 相關區塊 50 個以上 |
| DR-12 | 讀後創造任務與文本結構或主題直接連結，附句型框架 | 閱讀→寫作是第三常見的轉換 |
| DR-13 | 討論或合作的步驟寫明對象與方式，附討論用語 | 討論／分享 30% |
| DR-14 | 教師很少做 Exit ticket；產生器預設加入時題數要少 | 收尾反思 19% |
| DR-15 | 分級版本、學習目標、參考答案在現有學習單少見，是產生器的新增價值 | 14%／≤25%／9% |
| DR-16 | 指示語以英文為主，與規格一致 | 82% |

注意：這批資料以龍騰版（57%）與少數幾位產量高的設計者為主，規則描述的是「這批學習單」，不是所有教師。

候選清單（僅列編號）：**W048、W086、W096、W238、W078、W079、W089、W093**；prompt 實際放前 3 份。

## 5. Prompt chain

每一步都是「system 說明＋ user 模板（`{{變數}}`）＋ strict JSON schema ＋自動檢查」，與現有 `api/src/ai/` 的形狀相同，可直接變成 `prompt_versions` 的新 key。說明文字用繁體中文；會印在學習單上的欄位（`*_en`）一律英文。

| 步驟 | prompt key | 輸入 | 輸出重點 | 主要的硬性檢查 |
|---|---|---|---|---|
| (a) 逐段教材分析 | `sop_passage_analysis` | 已編號段落 | 每段的功能、摘要、1–3 個寫作特色＋**逐字證據**；全文語言重點 | 段落一對一；證據必須是該段原文的連續片段；中文欄位為中文 |
| (b) SIOP 目標＋課綱連結 | `sop_objectives` | 教材、(a)、學生與時間、**可連結的條目清單** | 內容目標／語言目標分開；理由；連結的 `item_code`；無合適條目時 `unlinked` | 兩類目標都有；**代碼必須在清單內**；linked/unlinked 與連結數一致；目標不可照抄條文 |
| (c) 逐段問題／任務 | `sop_paragraph_tasks` | 教材、(a)、已確認目標、教師勾選（可空） | 活動區塊：資訊處理功能、學生任務、每題作答方式、題目、答案、逐字證據 | 標籤只能來自規格 §2/§5；每段都涵蓋且依序；至少 3 種功能；證據逐字；全英文；選擇題 4 選項且答案在選項中；題幹不含答案 |
| (d) 暖身 | `sop_warmup` | 教材、目標、任務概要、**程式算出的候選字彙（含級別）** | 1–2 個背景知識活動；5–8 個關鍵字（語境句、英文釋義）；字彙小練習 | 關鍵字只能來自候選清單；**模型不輸出級別，級別由程式從詞彙表帶入**；語境句逐字；全英文 |
| (e) 三種鷹架 | `sop_scaffolds` | 目標、暖身、任務含答案 | 每個區塊與暖身的語言／教學／程序鷹架；三個版本的增減說明 | 目標區塊完全對應；每個區塊至少 1 個程序鷹架；種類只能來自規格 §3；全英文；不含答案原文 |
| (f) Exit ticket | `sop_exit_ticket` | 目標、任務概要 | 2–4 題：形成性評量（連到目標、附參考答案）＋反思或蒐集問題 | 題數；至少一題形成性且連到有效目標；至少一題反思／蒐集問題；不重複主要任務題目；全英文 |
| (g) 學習單組裝 | `sop_worksheet` | (b)–(f) 的 JSON、產生設定、版本 | 每個版本一次呼叫：學生版 sections ＋教師版答案與說明 | 暖身在主要任務之前、Exit ticket 在最後；核心區塊與設計一致；**學生版全英文且不含答案文字或答案標記**；每題都有教師版答案；跨版本：核心區塊相同、支持量基礎≥一般≥進階 |

完整檢查清單在 [`chain/checks.py`](../research/sop-validation/chain/checks.py)（硬性＝不通過就退回重做；軟性＝品質提示）。學生版 schema 本身沒有答案欄位，答案只存在 `teacher.answers`。

### 6.3 有／無「設計規則＋代表性範例」（P2、P4 × 2 輪）

對照組與實驗組共用同一份 (a)(b)(d)(f)，只重新產生 (c)(e)(g)。

| 步驟 | 無規則：第 1 次全過／修復後 | 有規則＋範例：第 1 次全過／修復後 | 延遲中位數（無／有） |
|---|---|---|---|
| (c) 逐段問題／任務 | 1/4／4/4 | 0/4／3/4 | 53／22 秒 |
| (g) 學習單組裝 | 10/12／11/12 | 5/12／11/12 | 117／32 秒 |

（延遲差異主要來自兩組在不同時段執行，不能歸因於 prompt。）

- **自動檢查沒有變好，第一次通過率反而較低**。新增的失敗類型：規則裡的「讀前→讀中→讀後」讓模型在主要任務裡又放了一個讀前討論區塊（與 (d) 暖身重複、打亂段落順序、沒有連到目標）；prompt 變長後 (g) 失控輸出也較多（12 次中 3 次，對照組 1 次）。
- **內容上的差別（人工閱讀）**：有規則時，開放題會附句型開頭（"I think ... because ..."）、指示語變成 Step 1／Step 2、表格會先填一格示範、題數略多（P2 由 11 題增為 13 題）。這些確實更像教師自製學習單。
- 判讀：規則有用但要改寫成不與 (d) 衝突的形式（讀前活動只在暖身步驟處理）；只含活動骨架的範例看不出獨立的效益，而且讓 prompt 變長。規則與範例的效果要靠教師盲評才能確認，自動檢查量不到「像不像教師會出的題」。

### 6.4 不給條目清單時的課綱代碼（(b) 的對照）

同樣的 prompt 拿掉條目清單，要求模型寫出代碼並默寫條文，4 篇 × 2 次：

| 引用數 | 代碼格式上存在 | 默寫的條文與真正條文相符 |
|---|---|---|
| 31 | 31 | **0** |

例：模型引用 `3-Ⅴ-2` 並說它是「閱讀並理解不同體裁的英文文本，並能擷取重點資訊」，實際的 3-Ⅴ-2 是「能看懂常見的英文標示」。因為代碼是連號的，隨便寫都會「存在」，所以**只檢查代碼存在是不夠的**；必須給清單（模型看得到條文才選得對），而且顯示的條文一律取自資料庫。

## 7. gemma 能做與不能可靠做的事

**可以可靠做到（有檢查時）**

- 依 strict JSON schema 輸出；規格 §2、§3、§5 的標籤逐字使用（enum 約束下沒有出現集合外的標籤）。
- 中文說明、英文學習單內容分開；學生看得到的欄位幾乎不會混入中文。
- SIOP 內容目標與語言目標的區分，目標具體、有理由；從給定清單挑課綱條目而不自創代碼。
- 依段落設計不同資訊處理功能的題目，並給出答案與出處。
- 暖身、Exit ticket、三種鷹架的內容生成。
- 接受檢查回饋後修正「內容型」的錯誤（非逐字證據、漏連目標、混入中文）。

**做不到或不穩定**

- 逐字引用的自律：會拼接、會省略，必須由程式比對。
- 長陣列完整性：可能提早結束，而且「請修正」無效，要重新生成。
- 長輸出：慢，且有機率失控到 `max_tokens`；同樣的請求重試會拿到快取。
- 憑記憶引用課綱：代碼像真的，內容是錯的。
- 判斷詞彙級別：本次完全不讓模型做。
- 防止「換句話說」的答案洩漏；真正依難度改寫題目（版本差異多半只是鷹架多寡）。
- 自由文字輸出乾淨：會夾帶 LaTeX／Markdown。

## 8. 決定性的詞彙級別分析（規格 §9.6 的子集，無 LLM）

[`vocab/analyze.py`](../research/sop-validation/vocab/analyze.py)：輸入學習單文字與目標級別，輸出

- 各級詞次與不同詞數、比例，**並列出分母**（可對應到詞彙表的詞；專有名詞、未收錄詞、複合詞、附錄詞不計入，另列）；
- 超出目標級別的詞及其位置（行、欄、前後文）；
- 另外分開列出：專有名詞、未收錄／無法判定、連字號與複合詞、附錄詞彙（數字、星期、國名…）、規則衍生的推定對應、詞形歧義、一詞多級。

詞形還原方式（純規則，不用模型，之後可直接移植到 Rust）：原形比對 → 不規則變化表（187 個基本詞、256 個變化形）→ 詞尾規則（-s/-es/-ies、-ed、-ing、重複子音、-er/-est、所有格、縮寫）。有多個候選時用詞彙表的詞類挑選（`used`→use 而非 us）。詞彙表編輯原則明寫「不列入」的規則衍生（re-、non-、un-、-less、-ly、-ness）另成一類「推定對應」，會標示規則，不混入一般比對。

4 篇文章的結果（目標第 4 級）：

| 文章 | 計入詞次／不同詞 | 未計入（專名／未收錄／複合／附錄） | 各級詞次比例（1→6 級，%） | 超出第 4 級的詞（例） |
|---|---|---|---|---|
| P1 | 290／176 | 0／5／3／0 | 61／15／15／5／4／2 | conserve、discard、disposable、momentum（6 級）等 14 個 |
| P2 | 464／230 | 7／7／8／10 | 73／14／6／5／2／0.4 | geographical、hygiene（6 級）等 8 個 |
| P3 | 475／230 | 17／23／12／5 | 70／12／10／5／2／2 | destined、inhabit、starvation（6 級）等 16 個 |
| P4 | 340／187 | 5／0／2／8 | 85／8／3／3／0.3／1 | electrician、headphone（6 級）、civic（5 級） |

已知限制：

1. **沒有詞性與詞義消歧**。`broke`（形容詞，第 4 級）與 break 的過去式無法區分：取較低級並列入「詞形歧義」。一詞多級（如 capital）取最低級並標示。
2. **片語完全偵測不到**（詞彙表沒有片語，程式也無片語表）；可用 `--phrases` 提供清單。連字號詞（flood-resistant）與閉合複合詞（classroom→class+room）只列出組成詞級別，不歸級。
3. **句首大寫的未收錄詞**無法判定是不是專有名詞（若同一詞在句中也以大寫出現才歸為專名）。
4. 原文較難的文章未收錄詞多（P3 有 23 個，如 ubiquitous、atoll、gyre），這些詞**不會被算進任何一級**，所以只看比例會低估難度——介面必須把「未收錄」的數量與清單放在比例旁邊。
5. 英式拼法、不在表內的不規則變化會落入未收錄；不規則表需要持續補。
6. 尚未用人工標註的語料量測還原正確率；上線前建議取 20 份學習單做人工核對。

## 9. 風險

| 風險 | 本次觀察 | 對策 |
|---|---|---|
| 捏造課綱代碼或條文 | 給清單時 58 筆引用全部在清單內；不給清單時 31 筆代碼都「存在」但條文 0 筆正確（§6.4） | 永遠提供條目清單、檢查代碼必須在清單內；顯示的條文、版本、頁碼一律由資料庫帶出，不採用模型寫的文字；找不到就標示「尚未完成課綱連結」 |
| 證據非逐字 | 模型常用「...」把兩句接起來，或改寫一兩個字 | 逐字檢查為硬性檢查；修復一次；仍不過就不顯示該筆證據 |
| 答案洩漏到學生版 | 字面洩漏可擋；**換句話說的洩漏擋不住**（例如基礎版的「簡化摘要」直接講出簡答題答案） | 學生版 schema 無答案欄位＋字面檢查；鷹架改由程式依版本挑選（見 §10）；教師預覽時並排顯示答案與鷹架 |
| 著作權 | 課綱、詞彙表、學習單、課文都受保護 | 原始檔與擷取文字不進 repo；範例只用去識別的活動骨架；教材原文只在教師自己的工作區使用；詞彙表頁首聲明「僅供非營利目的使用，轉載請註明出處」，營利使用需書面授權，上線前需確認平台使用方式是否在範圍內 |
| 個資 | 學習單含教師姓名、校名 | 範例不含原文；若日後要用原文片段，需教師同意並去識別 |
| Context 與輸出長度 | 輸入不是問題；輸出長、慢、偶爾失控或逾時 | 每步設 `max_tokens`、逾時、重試；版本分開呼叫；可局部重生 |
| 服務穩定性 | 同一天內速度差 2–3 倍，有逾時 | 佇列化、顯示進度、失敗可續跑；不要讓教師等一個同步請求 |
| 評估規模小 | 4 篇文章、每步 8 次；人工判讀由 AI 代理進行 | 見 §11 的後續驗證 |

## 10. 建議的 chain 設計與防護

1. **維持分步、每步一次呼叫、每步讓教師確認**。這與 SOP 的順序一致，每步輸出小（多在 2,500 tokens 以內）、失敗時只需重做一步，也自然支援「只重新生成單一題目或單一區塊」。
2. **能用程式決定的就不要交給模型**：
   - 詞彙級別與候選字彙：查詞彙表（已實作）。
   - 課綱條文、版本、頁碼：由資料庫依 `item_code` 帶出。
   - **學習單組裝 (g) 建議改成程式組裝**：section 順序、題號、教師版答案直接取自 (c)(d)(f) 的輸出；模型只負責「版本調整」這一小步（輸出：要改寫的題目、每個版本要顯示哪些鷹架的代號）。理由見 §6：(g) 是最慢、最長、也最容易出現順序、漏答案、洩漏答案等問題的一步，而這些問題在程式組裝下不會發生。
   - 鷹架的版本增減用規則：基礎版顯示全部；一般版顯示程序鷹架＋字詞表或句型框架；進階版只留程序鷹架。
3. **每次呼叫的固定防護**：`max_tokens`（預期輸出的 2–3 倍）、逾時 120–180 秒、指數退避重試、temperature 0.2；enum 陣列在程式端去重複。
4. **檢查與修復**：硬性檢查不過 → 把上一次輸出與失敗清單回給模型修一次（本次多數可修復，見 §6.1）→ 仍不過時不要整份擋下，而是移除或標示有問題的項目（例如拿掉非逐字的證據、未通過的課綱連結改為 unlinked），並在教師介面說明。未通過檢查的課綱代碼一律不顯示。
5. **輸出清理**：去除 LaTeX／Markdown 殘留；學生版字串含中文即退回。
6. **證據存位置**：逐字比對成功後由程式記下證據在教材中的起訖位置，可直接供規格 §4.4 的並排檢視與標示使用。
7. **(b) 的條目清單**整包提供該學校類型的高中階段條目；清單與版本隨生成紀錄保存。
8. **紀錄**：沿用現有的 `ai_interactions`、`teacher_decisions`、`retrieval_logs`，保存 prompt 版本、輸入摘要、輸出、檢查報告與教師的採用／修改／刪除。
9. **版本各自生成**：三個版本互相獨立，符合規格「可只選一個或兩個版本」；跨版本一致性（核心區塊相同、支持量遞減）由程式檢查。

## 11. 建議的實作順序

1. **知識庫與詞彙分析（不需 LLM，可先做）**：決定綜合型高中的 `school_track`、補上官方連結與版本標示後匯入課綱條目；新增詞彙表資料表；把 `vocab/analyze.py` 移植成後端端點。這一步就能交付規格 §9.6 的詞彙級別分析。
2. **(a) 教材分析 ＋ (b) SIOP 目標與課綱連結**：風險最低、價值最高，檢查邏輯與現有 `material_focuses` 的逐字檢查同型，可沿用現有 pipeline。
3. **(c) 逐段問題／任務、(d) 暖身、(f) Exit ticket**：逐步讓教師確認；先不放設計規則，等教師確認規則後再加。
4. **(e) 鷹架 ＋ 程式組裝學生版／教師版 ＋ 版本調整**，之後才接 DOCX／PDF 匯出。
5. **設計規則與範例**：請教師逐條確認 `design_rules.json` 後放入 (c) 的 prompt；範例是否使用依 §6.3 的結果決定。
6. **歷屆考題分析**：等資料來源與授權確定後另行評估（目前無資料）。

同時要做的驗證工作：固定一組回歸文章（至少 20 篇、涵蓋三種學校類型與不同文體，可放進現有的 `eval_sets`／`eval_runs`）；請 2–3 位教師盲評產出（目標是否具體、題目是否可用、鷹架是否合適，可用 `expert_ratings`）；累積教師採用率。本次只有 4 篇文章、每步 8 次，通過率的誤差範圍很大，只能當方向性的證據。

## 12. 規格 §12 各項的回覆

### 第 5 項：如何從學習單萃取並驗證結構化設計規則

- **萃取**（已完成第一版）：文字擷取 → 模型依固定 schema 逐份標註（活動順序、資訊處理功能、學生任務、作答方式、鷹架、暖身、收尾，全部使用規格的標籤）→ 統計 → 每條規則附證據數字與對應的自動檢查（§4.4，`rules/design_rules.json`）。
- **驗證**分四層：
  1. 標註正確率：本次由 AI 代理抽查 16 份（§4.2）。正式驗證建議由 2 位教師各自判讀 50 份、計算一致性，目標關鍵欄位 ≥85%；「學習單類型」需先把綜合講義與課文閱讀理解的定義寫清楚。
  2. 與關鍵字規則交叉比對，差異大的欄位（暖身、學習目標）不當作精確比例使用。
  3. 規則本身請主持人或教師逐條確認（採用／修改／刪除）；規則檔是 JSON，可直接附意見。
  4. 成效：同一批文章比較「有／無規則」的自動檢查通過率（§6.3），並請教師盲評兩組產出。
- **待補**：實收 270 份而非 276 份；兩份清單 CSV 未收到，無法核對來源與納入理由。

### 第 6 項：代表性範例的選取標準、去識別與成效驗證

- 選取標準、候選編號與去識別方式見 §4.5。第一版只用活動骨架，不用原文。
- 成效：見 §6.3。結論是活動骨架型範例加上規則後，自動檢查通過率沒有提高、第一次通過率較低，但題目寫法較接近教師慣例；是否採用應以教師盲評決定，第一版建議只放（經教師確認、改寫過的）規則，不放範例。
- 若要改用含原文的範例（更接近教師語氣），前提是：教師同意、移除姓名／校名／班級／網址，並確認教科書課文片段不在範例內。

### 第 15 項：SIOP 目標推薦、課綱連結與驗證

- **流程**：(a) 先逐段分析教材 → (b) 以教材、(a) 的結果、學生資訊、課堂時間為輸入，分別產生內容目標與語言目標，每項附理由、對應段落與課綱連結。System prompt 明寫兩類目標的定義與「不可照抄條文」。
- **條目怎麼給**：現有 `retrieval.rs` 是字面比對，而教材是英文、條文是中文，直接檢索對不上。因為 context 充裕，本次作法是把該學校類型**高中階段的全部條目（普通型 147 條，約 6 千 tokens）整包放進 prompt**，由模型挑選。若日後條目變多，再改成用 (a) 的中文分析結果做檢索。
- **追溯**：模型只輸出 `item_code`；介面顯示的條文、類別、來源文件、版本、頁碼全部由資料庫帶出，並保存該次生成時的條目版本。
- **不捏造**：代碼不在清單內即為硬性失敗；沒有合適條目時輸出 `unlinked`，介面標示「尚未完成課綱連結」，目標建議仍保留。
- **本次結果**：8 次 (b) 全部第一次通過硬性檢查；30 個目標、58 筆連結的代碼全在清單內；兩類目標每次都同時出現；沒有照抄條文。模型從未輸出 unlinked（清單涵蓋面廣，總找得到沾邊的條目），所以「找不到就標示」這條路徑本次沒有被實際觸發，需要另外用無關教材測試。
- **正確性驗證方法**：
  1. 自動：兩類目標都存在、代碼存在、linked/unlinked 一致、目標與條文的字面重疊低於門檻。
  2. 連結相關性需要人判讀：建議每學期抽 50 筆「目標—條目」配對，由教師標示相關／勉強／不相關；本次由 AI 代理檢視 28 筆，25 筆明確相關、3 筆只有主題沾邊（都是 8-Ⅴ-7），沒有明顯錯誤的連結；這只是初步判讀，不能取代教師判讀。
  3. 上線後記錄教師對每項建議的採用、修改、刪除，作為持續指標（現有紀錄機制可沿用）。
  4. 固定一組回歸用文章，每次改 prompt 或換模型時重跑自動檢查。

### 第 17 項：詞彙表的詞形正規化與計算方法

做法與限制見 §8。逐項回覆：

| 規格要求 | 做法 |
|---|---|
| 區分詞形變化與基本詞形 | 每個詞記錄原樣、還原後的基本詞形與比對方式（原形／詞形變化／規則衍生） |
| 多義詞、一詞多級 | 不做詞義判斷；一詞多級取最低級並列入「多級別詞」清單；詞形歧義（broke、learned）取較低級並標示 |
| 片語 | 詞彙表不含片語；預設不歸級，另列；可由計畫提供片語表後偵測 |
| 專有名詞 | 句中大寫且不在表內→專有名詞，另列、不歸級；附錄中的國名、月份等另列為「附錄詞彙」 |
| 未收錄詞 | 另列並附位置與前後文，不歸入任何一級 |
| 數量與比例 | 同時給詞次與不同詞兩種算法；分母＝可對應到詞彙表的詞；介面須同時顯示分母與未計入的數量 |
| 版本 | 結果中記錄詞彙表版本；分析結果需綁定學習單版本（規格 §9.7） |
| 級別來源 | **一律查表，模型不產生級別**；(d) 暖身的關鍵字也只能從程式算出的候選清單挑 |
