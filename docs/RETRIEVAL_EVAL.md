# 課綱檢索評估：關鍵字 vs. 混合（關鍵字＋語意向量）

2026-11-15。程式在 [`research/retrieval-eval/`](../research/retrieval-eval/)，逐題數字在 `results.json`。實作見 [API.md](API.md)「Phase 2.4」。

## 結論

- **混合檢索明顯優於只用關鍵字**，預設採用（設定了 `EMBEDDING_PROVIDER` 時）。31 題中 recall@8 有 23 題變好、1 題變差；MRR 18 題變好、0 題變差。
- 差距主要來自**英文查詢**：教材與目標常是英文、條文是中文，關鍵字一條都找不到（15 題英文查詢 recall 全為 0），語意向量能找到 77%（@8）。中文查詢也有提升（recall@8 0.54 → 0.69）。
- 對課例 SOP 目標最重要的是**技高**：技高可連結的條目有 331 條，超過 prompt 上限 150 條，原本靠關鍵字挑、不夠再依代碼補滿，標註條目只有 56% 會進到 prompt；混合檢索為 98%。普高（147 條）與綜高（112 條）不到上限，照舊全部給模型，不受影響。
- 混合與「只用向量」相比差距小（recall@8 0.708 vs 0.682，MRR 0.838 vs 0.855），在這個題數下屬於雜訊範圍。仍選混合：關鍵字對中文查詢中出現的條文原句、精確詞（例如「商業書信格式」）有幫助，且模型故障時行為一致地退回關鍵字。

## 方法

- **模型**：國網中心 `embeddinggemma-2`（768 維，回傳已正規化的向量）。條目與查詢皆用同一模型，無前綴指令。
- **條目範圍**：與 app 預設相同：高中階段（Ⅴ）、英語相關科目（英語文、外語群的英語、職場），依學校類型過濾。普高 147 條、技高 331 條。
- **查詢**：31 題（普高 15、技高 16；中文 14、英文 15、中英混合 2），模擬教師會送出的內容：一句學習目標、教材摘要、短的搜尋詞、教案（標題＋目標＋步驟）、SOP 目標步驟的輸入（標題＋教材全文）。
- **標註**：每題可接受的課綱代碼（2–13 個）由開發者（Claude）讀官方條文後判定，**不是教師的判斷**；寬鬆程度以「熟悉課綱的人會認為相關」為準。題數少、單人標註，數字只能看大方向。
- **指標**：app 實際用到的 k：8（教案建議 `RAG_TOP_K`）、20（課綱查詢預設筆數）、150（SOP 目標的條目上限）；以及 MRR（第一個相關條目名次的倒數）。
- **一致性**：評估程式的關鍵字排序與融合是 Rust 程式的逐行移植；已用同一份資料對 Rust 函式（`retrieval::rank`、`retrieval::rank_hybrid`）比對，31 題的關鍵字排序與混合前 20 名完全相同。

## 結果（31 題平均）

| 方法 | recall@8 | recall@20 | recall@150 | MRR |
|---|---|---|---|---|
| 只用關鍵字（現行） | 0.259 | 0.348 | 0.433 | 0.405 |
| 只用向量 | 0.682 | 0.811 | 0.988 | 0.855 |
| **混合（採用）** | **0.708** | **0.850** | 0.988 | 0.838 |

| 分組（題數） | 關鍵字 recall@8 / MRR | 混合 recall@8 / MRR |
|---|---|---|
| 普高（15） | 0.283 / 0.456 | 0.837 / 0.889 |
| 技高（16） | 0.237 / 0.358 | 0.587 / 0.791 |
| 中文（14） | 0.543 / 0.824 | 0.690 / 0.893 |
| 英文（15） | 0.000 / 0.000 | 0.769 / 0.824 |
| 中英混合（2） | 0.214 / 0.517 | 0.381 / 0.562 |

SOP 目標（上限 150，排序後依代碼補滿，與 `curriculum::items_for_track_hybrid` 相同）：技高標註條目進到 prompt 的比例 關鍵字 0.564 → 混合 0.977。

## 例子

**混合勝出**
- G02「Students will be able to distinguish facts from opinions in an editorial…」：關鍵字 0 筆；混合前 3 名 D-Ⅴ-3（客觀事實及主觀意見的分辨）、Ae-Ⅴ-12（敘述者的觀點、態度）、3-Ⅴ-15。
- V09「學生能用英語描述身體不舒服的症狀，並在藥局購買藥品」：關鍵字第 1 名是英語Ⅰ-F-a「教室、學校、課程之描述」（只共用「描述」），正解排第 5；混合前 2 名就是英語Ⅱ-F-c（藥房買醫療用品）、F-a（不適情況）。
- V10「An article about recycling and protecting endangered animals…」：混合前 6 名全部是標註條目（生態、環保語彙、環境永續、全球永續）。
- V16（求職面試的英文對話全文）：關鍵字 0 筆；混合第 1 名英語Ⅶ-H-b 求職信、第 3 名履歷表。

**關鍵字較好或兩者都弱**
- V13「學生能運用閱讀策略理解段落大意，並寫出結構完整的英文段落」：關鍵字 recall@8 0.46，混合 0.38，是唯一 recall@8 變差的題目。關鍵字正好命中英語Ⅳ–Ⅵ 的長條文（「閱讀策略」「段落」原詞），向量則偏向語意相近但較泛的 7-Ⅴ-5、7-Ⅴ-6（學習策略）。
- G15、V15（教案或教材全文，中英混合）：兩種方法各有一題較好。G15 的中文目標與步驟命中條文原詞，關鍵字 MRR 1.00、只用向量 0.50，混合維持 1.00；V15（餐廳對話全文）只用向量 recall@8 0.67，混合被「聽懂常用句型」這類因「句」「聽」等字命中的條目擠掉一半，降到 0.33（仍優於關鍵字的 0）。長教材先摘要再檢索（例如用 SOP 第 (a) 步的中文分析當查詢）是可行的改進，本次未做。
- V06「product presentation with well-designed slides」：職場Ⅰ（簡報）的條目都很短（「產品簡報」），英文查詢與「英語Ⅴ–Ⅵ 參與課堂討論、分享意見」這類長條文更接近，recall@8 只有 0.12。

## 調整過的設定

- **條目要嵌入的文字**（`kb_embeddings::embed_text`）：比較四種（純條文、科目｜學習表現或內容｜類別名稱：條文、前者再加官方代碼、embeddinggemma 建議的 `title: … | text: …` 格式）。混合 recall@8 分別為 0.684、**0.708**、0.667、0.632，差距不大；採用第二種。代碼對模型只是無意義的符號，精確代碼查詢本來就由 `curriculum_by_codes` 處理。
- **融合方式**：加權倒數排名融合（RRF，k = 60），關鍵字項乘上「該條分數／最高分」。純 RRF 會讓只共用一個二字組的條目跟命中十個詞的條目得到差不多的加分；加上比例後 recall@8 0.687 → 0.708、recall@20 0.815 → 0.850。k（20、60）與關鍵字權重（1.0、0.5、0.3）的組合都在 ±0.02 內，維持 k = 60、權重 1：1。
- **相似度門檻**：不設。標註條目的相似度 0.63–0.92，而離題查詢（量子力學、烘焙、股票K線）的最近條目也有 0.60–0.75，兩者重疊，門檻擋不掉離題查詢卻會丟掉正解。因此有設定模型時，任何查詢都會回傳最接近的條目；教案建議原本「知識庫查無」不呼叫模型的情況，只剩關鍵字也沒有、條目也還沒建索引時才會發生。

## 限制

- 31 題、單人標註；沒有教師參與。正式採用前宜請 2–3 位教師各標 20 題，重算一次。
- 只評估課綱條目。教案建議同時檢索文法、詞彙教學、SIOP 與教師經驗；目前這些多是示範條目，沒有可評估的正式資料（教師經驗沒有向量，只靠關鍵字參與排序）。
- 一次查詢約 0.3 秒；請求內等待上限 2.5 秒（`EMBEDDING_QUERY_TIMEOUT_MS`），超過就只用關鍵字。
