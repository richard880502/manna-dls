## 1. 設計原則

1. **一個畫面一件事。** 每頁只有一個實心按鈕，其餘是外框按鈕或文字連結。
2. **用留白、字級和細線分段，不用框。** 只有三種東西有底色：Manna 的建議（金）、教材（印刷紙）、學習單（印刷紙）。
3. **三種聲音一眼分得出來。** 教材原文＝襯線字、白紙、頁邊段落編號；老師寫的＝一般內文與藍墨水（選取、註記、主要按鈕）；Manna 產生的＝金色底加星號，並帶理由與來源。
4. **不擋路。** 沒有必填、沒有「儲存」按鈕（自動儲存，版本紀錄放在一個連結後面）；每一步都能略過；AI 的東西要老師按了才寫進去，而且先看到會改哪裡。
5. **說老師的話。** 不出現「版本」「Phase」「RAG」「選用」這類系統用語；導覽與按鈕全部中文。CoRe 在介面上叫「單元想法」，小字保留 CoRe。
6. **班級是情境，不是欄位。** 從哪個班進來就是哪個班，畫面上只在麵包屑出現一次。

## 2. 資訊架構與導覽

```
班級（首頁）
 └ 班級頁：下一節 → 開始上課｜這班的單元｜上課紀錄（補寫、回顧）｜班級特性
備課庫
 └ 單元：課例清單 ＋ 單元想法（CoRe，旁欄，隨時可補）
     └ 課例：七步備課 → 產生學習單 → 開始上課
學習單
 └ 直接做一份（不經課例）｜做過的學習單
右上角帳號：備課偏好、登出
```

- **導覽只有三項：班級、備課庫、學習單。** 改成頂端一列（手機在底部），把橫向空間還給「教材並排」。
- **2026-11 簡化（產品負責人核可）：導覽改為「班級｜學習單｜教材」。** 單元從所屬班級進入；備課庫（所有單元，`/units`）從班級頁與首頁進入，`/library`、`/plan` 轉到那裡。課例頁只剩七步，結尾是「產生學習單」，「開始上課」在頁首；單元頁以課例清單為主，單元想法收成一行；班級特性只在班級頁寫；不再強制初次使用設定。
- **2026-11 再簡化：過去的作品只在一個地方。** `/prep` 改名「我的作品」，同一份清單列出備課對話與不屬於備課對話的獨立學習單（新到舊，可依類型篩選）；`/worksheets` 清單轉到那裡，「直接做一份」表單移除（上方結構圖的「學習單」一節是舊版）。
- 拿掉：Reflect & Progress、Share & Connect、履歷頁、社群動能地圖、「本輪平台範圍 Phase 1」面板。做出來之前不放入口。
- 「Teach & Record」不再是導覽項目：上課從班級開始，紀錄在班級頁。
- 「AI 資深教師」不是頁面，是課例與學習單畫面右上角的金色按鈕，開在右側、不遮住工作區。

## 3. 課例備課的兩個方向

兩個方向內容完全相同（同一課、同樣的目標、任務、建議），只差在組織方式。

| | **A　一步一步**（[目標](design/overhaul/lesson-a.html)、[問題與任務](design/overhaul/lesson-a-tasks.html)） | **B　單頁工作區**（[畫面](design/overhaul/lesson-b.html)） |
|---|---|---|
| 畫面 | 左邊七步進度，中間一次只有一步；Manna 的建議就在那一步、那一段下面；課文段落引在題目上方 | 左邊整篇教材，中間七步可收合，右邊一欄集中放 Manna 的建議 |
| 焦點 | 很清楚：這一步的問題，和「下一步」 | 分散：三欄同時在說話，主按鈕是「產生學習單」 |
| 適合 | 第一次用、新手教師、需要被 SOP 帶著走的時候；手機上直接可用 | 熟手來回修改、需要一直對照全文的時候 |
| 風險 | 來回跳步驟要多按幾下；看不到整篇教材（要另開） | 資訊量大，容易回到「一堆表單」的觀感；1100px 以下三欄放不下；建議離它對應的內容較遠 |
| 實作量 | 較小：一個步驟一個元件，可以一步一步上線 | 較大：三欄捲動、收合狀態、建議與段落的對位都要處理 |

**建議採用 A 作為預設**，並從 B 借一件事：A 的每一步右上放「對照教材」，按了教材從左側滑出並排（與學習單產生器同一個教材檢視元件）。理由：
- 九位教師裡六位卡在「目標」，新手卡在目標與考點、資深卡在差異化與時間，都是「一次想清楚一件事」的問題，A 正好一次只問一件事。
- 原本頁面最大的毛病是沒有焦點、框太多。B 天生三欄，要做到不亂的成本高。
- A 的右側留白正好是「AI 資深教師」的位置（[畫面](design/overhaul/lesson-chat.html)），不必再擠一欄。
- B 的優點（全文對照、總覽）可以用「對照教材」和進度列的每步摘要補上。

## 4. 六個問題怎麼解

| # | 原本的問題 | 解法 |
|---|---|---|
| 1 | 沒有焦點，主任務和建議欄一樣重 | 首頁與班級頁最上面只有「下一節＋開始上課」；備課頁一次一步，建議縮在該步驟內、排在老師自己的內容之後 |
| 2 | 框中有框 | 清單改成細線分隔的列；面板框全部拿掉；只有 Manna 建議、教材、學習單三種有底色的面 |
| 3 | 班級問兩次 | 拿掉「目前班級」下拉與「這節課是哪一班？」。從班級進來＝已知班級，直接開始；只有從備課庫按「開始上課」時問一次（[畫面](design/overhaul/start-class.html)），預設選「下一節正好是這節」的班 |
| 4 | 兩個主按鈕並排、按鈕上有系統用語 | 沒有「儲存教案（產生新版本）」：改自動儲存，右上小字「已自動儲存 14:32　版本紀錄」。備課頁的主按鈕是「下一步」；「開始上課」在首頁與班級頁才是主按鈕 |
| 5 | 側欄滿是還沒做的入口、開發者面板、中英混雜 | 導覽剩三項中文；未完成的功能與 Phase 面板全部移除 |
| 6 | 說明文字與標籤太吵 | 拿掉「目前第 1 版（共 1 版）」「未設定上課日期」「都可略過」「選用」。可略過的事只在進度列下說一次；標籤只留有資訊的（任務功能、順利／卡住、尚未完成課綱連結） |

其他對應規格的地方：
- 學習單四個區塊與所有標籤逐字照規格第 5 節；「學生任務」用五個小標分組；由課例帶入的選項有金色星號，可取消；全部不選也能按「產生學習單」。
- 教材並排、文字註記（藍色底線，註記不改原文）、每則註記自己勾「提供給 AI」。
- 結果頁：版本分頁、學生版／教師參考版切換（答案只在教師版，金色）、單一區塊「重新產生」後整塊變金色並可「復原上一版」、改動不自動回寫教案（一行提示問要不要同步）。
- 目標：內容目標、語言目標分開；每項建議有理由、課綱連結與來源；找不到來源時標「尚未完成課綱連結」。
- 程序鷹架標「自動產生」（金色字），可修改。
- 完成前檢查另開一頁，最上面就寫明不是官方認證；百分比旁邊寫分母與算法。

## 5. 對 `DESIGN.md` 的修改建議

保留「兩種墨水」：老師＝藍墨水，Manna＝金。以下是變動：

| 項目 | 現況 | 建議 |
|---|---|---|
| 外殼 | 16rem 側欄、九個入口、running head | 56px 頂端列、三個入口；760px 以下導覽移到底部。拿掉 running head（`01 · Study & Plan`） |
| 面板 `panel-card` | 每區一個有框面板 | **停用。** 區段＝標題＋細線分隔的列（`.rows`）。新增規則：一頁最多一層有底色的面 |
| 第三種聲音（新增） | 無 | `--color-sheet`（最亮的紙）＋ `--font-print`（襯線）：教材與學習單預覽用。段落編號放頁邊 |
| 教師註記（新增） | 無 | 藍色淡底＋底線標在原文上，註記文字在藍色淡底的小塊裡；絕不用金色 |
| Manna 內容 | 金底、無框 | 不變。新增：每塊開頭固定「星號＋Manna 建議＋類型」；由系統先選的選項用小星號標示 |
| 按鈕 | 每個區域一個實心 | 收緊為**每個畫面一個實心**。新增金色外框按鈕（只給「問資深教師」）。文字連結取代大部分小按鈕 |
| 收合區 `plan-section` | 課例頁第一屏以外都收合 | 若採 A：停用，改步驟進度列（`.rail`）。若採 B：保留，摘要列加「n 則建議」 |
| 標籤 | 多種 | 只留：任務功能、狀態（順利／卡住）、警示（尚未完成課綱連結）。13px 起 |
| 套用確認（新增） | 無 | 藍色 2px 框（老師的決定）：寫明會改哪裡、原本／改成對照、可復原 |
| 深度 | 只有 help sheet 有陰影 | 另加一處：選班級的對話框 |

對比（WCAG AA）已逐對計算（明亮改版後的數值）：內文 17.6:1、次要文字 10.9:1、說明文字 5.5:1（在最深的底上 4.7:1）、藍字在藍淡底 5.5:1、白字在藍鈕 5.1:1、金字在金底 7.7:1 與 7.1:1、順利／卡住／刪除各自在其淡底 5.7 到 6.1:1、輸入框與外框按鈕邊線 3.4:1 以上。鍵盤焦點：所有可操作元件都有藍色外框（5.1:1），選項籤與切換鈕的焦點框畫在可見的籤上。375px 與 1440px 寬全部畫面沒有橫向捲動；手機上的按鈕高 44px 以上。

## 6. 想請產品負責人決定的事

1. 課例備課採 **A（一步一步）還是 B（單頁）**？或 A 加「對照教材」？
2. **「單元想法」** 可以當 CoRe 在介面上的名字嗎（小字保留 CoRe）？還是研究上需要老師看到 CoRe 這個詞？
3. 導覽要不要把 **「學習單」** 獨立成一項？（規格要能不經課例直接使用，所以我放了；若希望老師盡量從課例進去，可以收進備課庫。）
4. 首頁的「接下來」目前依 API 的 `next_action` 取**最近上過課的班**。要不要讓老師輸入課表，才能真的知道「今天第幾節是哪一班」？
5. 手機上只做**上課（順利／卡住）與查看**，備課與學習單編修以電腦為主，可以嗎？
6. **「問資深教師」** 的主動邀請要多主動？設計稿目前只有按鈕，沒有自動跳出的邀請。

## 7. 建議的實作順序

1. **外殼與清單頁**：頂端導覽、拿掉未完成入口與 Phase 面板；首頁、班級頁、備課庫、單元頁改成細線列；班級只問一次。只動版面與樣式，接 `feature/classes-library` 現有 API。
2. **課例七步（方向 A）**：步驟進度列、每步一個畫面、自動儲存取代儲存按鈕、建議內嵌。先上已有資料的步驟（教材、目標、問題或任務），其餘步驟先給空白可填的版本。
3. **學習單產生器**：教材並排與註記、四個區塊、結果頁（版本、學生／教師版、單區塊重新產生與復原）、匯出。完成前檢查可以拆成後續一個 PR。
4. **AI 資深教師**：右側對話、套用前的對照確認與復原；之後再把「對照教材」加回課例各步。
